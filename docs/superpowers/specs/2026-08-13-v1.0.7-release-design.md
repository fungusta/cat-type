# Cat Type v1.0.7 Release

## Purpose

Publish the missing-caret pointer fallback as Cat Type v1.0.7. This patch
release makes Windows behave consistently with macOS and Linux: UI Automation
and Win32 caret providers remain preferred, but if neither produces usable
geometry the companion anchors beside the mouse pointer. UI Automation
password fields remain suppressed and never use the fallback.

## Version Metadata

The release version is `1.0.7`, with annotated Git tag `v1.0.7`. The release
commit updates all version-bearing locations:

- `app_version.py`: runtime and update-discovery version;
- `CatType.spec`: macOS bundle version;
- `packaging/CatType.iss`: Windows installer version;
- `packaging/version_info.txt`: Windows numeric and displayed file/product
  versions;
- `tests/test_release_version_check.py`: accepted and rejected versions; and
- `README.md`: example release tag.

## Validation and Publication

Before pushing, the release checker must accept `v1.0.7`, reject drift back to
`v1.0.6`, and the complete Linux CI-equivalent test selection must pass. The
pushed `main` commit must then pass the cross-platform build workflow on
Windows x64, macOS Intel, and Linux x64 before the tag is created.

The annotated `v1.0.7` tag is created on the exact tested `main` commit and
pushed once. The release workflow tests and packages these targets:

- Windows x64 installer: `Cat-Type-Windows-x64.exe`;
- macOS Intel disk image: `Cat-Type-macOS-x64.dmg`;
- macOS Apple Silicon disk image: `Cat-Type-macOS-arm64.dmg`;
- Linux x64 archive: `Cat-Type-Linux-x64.tar.gz`; and
- Linux arm64 archive: `Cat-Type-Linux-arm64.tar.gz`.

Publication is complete only after every build matrix job and the publish job
succeed, and the non-draft GitHub Release contains all five packages plus
`SHA256SUMS.txt`.

## Failure Handling

Do not push the tag if local validation or the pushed cross-platform build
fails. If pushing `main` succeeds but the tag push fails, keep the release
commit unchanged and diagnose the push before retrying.

After `v1.0.7` is pushed, treat it as immutable: do not move, delete, or
recreate the tag if a release workflow job fails. Diagnose the failed job and,
if code or metadata must change, prepare a new patch version and tag instead.
