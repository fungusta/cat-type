# Cat Type v1.0.5 Release

## Purpose

Publish the keyboard-aware paw animations and Settings-only session
keystroke counter as Cat Type v1.0.5. The release is a patch increment from
v1.0.4 because it adds a focused companion behavior without changing the
application's installation model or compatibility contract.

## Version Metadata

The release version is `1.0.5`, with Git tag `v1.0.5`. The release-preparation
commit will update every existing version-bearing location:

- `CatType.spec`: macOS bundle version;
- `packaging/CatType.iss`: Windows installer version;
- `packaging/version_info.txt`: Windows numeric `filevers` and `prodvers`,
  plus the displayed file and product version strings; and
- `README.md`: example release tag.

The numeric Windows fixed version will be corrected from its stale v1.0.3
value to `(1, 0, 5, 0)` so it agrees with the v1.0.5 display strings.

## Validation and Publication

Before publication, the repository release checker must accept `v1.0.5`,
reject `v1.0.4`, and the complete local 60-test selection must pass. The
release-preparation diff must contain only version and release documentation
changes.

After committing the release preparation on `main`, push `main` to `origin`,
create annotated tag `v1.0.5` on that exact commit, and push the tag. The
existing GitHub Actions release workflow will build and test these assets:

- Windows x64 installer;
- macOS Intel disk image;
- macOS Apple Silicon disk image;
- Linux x64 archive; and
- Linux arm64 archive.

The workflow will publish one GitHub Release containing all five artifacts
and `SHA256SUMS.txt`. Publication is complete only after every build job and
the publish job succeed and the GitHub Release is visible with tag `v1.0.5`.

## Failure Handling

Do not push the tag if local version or test validation fails. If pushing
`main` succeeds but the tag push fails, leave the release commit on the
remote and diagnose before retrying the tag. If a post-tag workflow job
fails, do not move or recreate the published tag; diagnose the failed job and
make a new corrective commit and version only if the immutable release needs
replacement.
