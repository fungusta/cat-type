# Cat Type v1.0.40 release plan

**Goal:** Publish the approved expanded achievements, items, and cape-fit change
as the next stable release.

**Architecture:** Keep `IS_BETA_BUILD=False`, synchronize all runtime and package
version metadata, and use the existing five-platform GitHub Release workflow.

## Preparation

- [ ] Confirm the release commit contains the approved catalog, SVG artwork,
  renderer layering, tests, and documentation.
- [ ] Update runtime, macOS, Windows metadata, version tests, README, and release notes to 1.0.40.
- [ ] Run the release-version checker, full local suite, focused artwork suite,
  and diff checks.
- [ ] Commit the verified release candidate.

## Publication

- [ ] Push the release commit to `main` without force.
- [ ] Create and push annotated `v1.0.40` from that exact commit.
- [ ] Wait for all five package builds and GitHub Release publication.
- [ ] Verify the tag target, release status, five packages, manifest, and checksums.
- [ ] Record release evidence in `docs/research/2026-09-10-v1.0.40-release-verification.md`.

Existing release tags and assets remain immutable. If a build fails, diagnose it
before publication; never move a published tag.
