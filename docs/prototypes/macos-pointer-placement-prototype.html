Where should the cat appear when macOS cannot see the text caret?

This demo tests a pointer-only state model for the Mac App Store build. The design question is whether the cat should use a recent click, the pointer at the first keystroke, or continuously follow the pointer—and when that position should be allowed to change.

✓
Working recommendation: recent click, then freeze for one typing burst.

Use a click from the last eight seconds because it often represents the field the user focused. Otherwise use the pointer at the first keystroke. Once visible, keep the cat still until it fades, then choose a fresh anchor for the next burst.

Privacy boundary

The smart strategy needs only an in-memory pointer coordinate and timestamp. It does not identify the clicked app or control and should never persist click history.

Password limitation

A pointer-only sandboxed app cannot know whether the focused control is a password field. The animation may appear there, but it still records no key identity or typed content.

Settings language

Call the setting “Cat position relative to pointer,” not “caret corner.” Explain that the cat stays where it appears until typing stops.

Feasibility gate

Before committing to recent-click anchoring, verify global mouse-click callbacks inside the signed App Store sandbox. If that fails, use the first-key pointer strategy.
